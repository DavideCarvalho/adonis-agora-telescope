The dashboard and its JSON API expose everything Telescope recorded — requests, queries,
exception stacks, diagnostic payloads. That is exactly what you want for debugging and
exactly what you must not leave open in production. Every route runs an **`authorize`
guard** first; this page is how that guard works and how to wire it to your needs.

## The default policy

With no `authorize` configured:

- **Outside production** → **open**. The dev dashboard just works.
- **In production** → every page and API request gets **`403`**.

Either way, this warning is logged once at boot:

```txt
[@adonis-agora/telescope] console has no `authorize` configured: it is open outside production and denies every request in production. Set `authorize` in config/telescope_ui.ts.
```

"Production" is the app's `app.inProduction` (`NODE_ENV=production`). There is no other
switch: to open the console in production, set `authorize`.

## Delegate to your app's auth

For real apps, gate the dashboard on your existing session and roles with `authorize`. It
receives the request's `HttpContext`, so `ctx.auth`, `ctx.session` and the rest are right
there. `authorize` is the whole policy, in every environment.

It takes the same three forms as every `@adonis-agora` console, so one authorizer can guard
all of them.

<Tabs items={['Function', 'Class', 'Lazy import']}>
<Tab value="Function">

```ts title="config/telescope_ui.ts"
import { defineConfig } from '@adonis-agora/telescope/ui'

export default defineConfig({
  authorize: (ctx) => ctx.auth.user?.isAdmin === true,
})
```

Sync or async:

```ts title="config/telescope_ui.ts"
export default defineConfig({
  async authorize(ctx) {
    await ctx.auth.check()
    return ctx.auth.user?.role === 'admin'
  },
})
```

</Tab>
<Tab value="Class">

Put the authorizer in its own file. It is built through the container, so `@inject()`
works:

```ts title="app/policies/console_access.ts"
import { inject } from '@adonisjs/core'
import type { HttpContext } from '@adonisjs/core/http'
import type { ConsoleAuthorizer } from '@adonis-agora/telescope/ui'
import AuditService from '#services/audit_service'

@inject()
export default class ConsoleAccess implements ConsoleAuthorizer {
  constructor(private audit: AuditService) {}

  async authorize(ctx: HttpContext) {
    const user = ctx.auth.user
    if (!user) return { redirectTo: '/login?next=/telescope' }
    await this.audit.record('telescope.open', user)
    return user.isAdmin === true
  }
}
```

```ts title="config/telescope_ui.ts"
import { defineConfig } from '@adonis-agora/telescope/ui'
import ConsoleAccess from '#policies/console_access'

export default defineConfig({
  authorize: ConsoleAccess,
})
```

</Tab>
<Tab value="Lazy import">

The same class, loaded on the first console request instead of when the config file is
read:

```ts title="config/telescope_ui.ts"
import { defineConfig } from '@adonis-agora/telescope/ui'

export default defineConfig({
  authorize: () => import('#policies/console_access'),
})
```

</Tab>
</Tabs>

Whichever form you use, `authorize` answers with one of:

| Return                                              | Page navigation              | API call         |
| --------------------------------------------------- | ---------------------------- | ---------------- |
| `true` / `{ allowed: true }`                        | allowed                      | allowed          |
| `false` / `{ allowed: false }`                      | `403` page                   | `403` JSON       |
| `{ allowed: false, reason: 'unauthenticated' }`     | `401` page                   | `401` JSON       |
| `{ redirectTo: '/login' }`                          | `302` to that path           | `401` JSON with `redirectTo` |
| throws                                              | `403` page                   | `403` JSON       |

### Token access with `authorizeByToken`

For scripts and machines that have no session, `authorizeByToken` allows a request whose
`Authorization` header is `Bearer <token>` and answers `401` to anything else:

```ts title="config/telescope_ui.ts"
import env from '#start/env'
import { authorizeByToken, defineConfig } from '@adonis-agora/telescope/ui'

export default defineConfig({
  authorize: authorizeByToken({ token: env.get('CONSOLE_TOKEN') }),
})
```

```sh
curl -H "Authorization: Bearer $CONSOLE_TOKEN" https://app.example.com/telescope/api/entries
```

Only the header is read: a `?token=` query string or any other header is refused. An empty or
missing `token` throws when the config loads, so a deploy without the secret fails at boot
instead of running with an unusable gate. Every `@adonis-agora` console exports the same
helper.

### Role-based gate via `@adonis-agora/authz`

If you use `@adonis-agora/authz` for RBAC (roles live in `user_roles`, or come from the
token claim), the `authorizeByRoles` helper is a ready-made `authorize` with the same
semantics as the `requireRole` middleware:

```ts title="config/telescope_ui.ts"
import { defineConfig } from '@adonis-agora/telescope/ui'
import { authorizeByRoles } from '@adonis-agora/authz'

export default defineConfig({
  authorize: authorizeByRoles({ roles: ['ADMIN'] }),
})
```

- The user comes from `ctx.auth.getUser()` (authkit) or `ctx.auth.user` (any guard), so it
  works with or without authkit, including a plain AdonisJS **session cookie**.
- `effectiveRoles` includes global token claims **and** app-level DB roles; `roles` is
  any-of (passes when the user holds at least one).
- No authenticated user → `401`; signed in without the role → `403`.
- Pass `loginPath` to send an anonymous page navigation to your login page instead
  (`authorizeByRoles({ roles: ['ADMIN'], loginPath: '/auth/login' })`); API calls keep
  getting JSON.

The same helper works across every `@adonis-agora` console, so one RBAC gate reads the
same everywhere.

## Signing in

The console has no login of its own: people sign in through your app. To send an anonymous
visitor to your login page, return `{ redirectTo }` from `authorize` (see
[Redirecting instead of answering JSON](#redirecting-instead-of-answering-json)), or point the
access-denied page's "Sign in" button at it with `accessDenied.loginHref`.

## Guard behaviour

The guard translates an `authorize` decision into an HTTP outcome. This mapping is the
dashboard-gate contract shared by every `@adonis-agora` console (telescope, durable, media,
payments, agent, authz):

| Outcome                                                     | Status | Meaning                                            |
| ---------------------------------------------------------- | ------ | -------------------------------------------------- |
| `authorize` returned `true` (or `{ allowed: true }`)       | —      | Request proceeds to the handler.                   |
| Denied with `reason: 'unauthenticated'`                    | `401`  | `{ "error": "unauthenticated" }` — please sign in. |
| Denied with `reason: 'forbidden'`                          | `403`  | `{ "error": "forbidden" }` — signed in, but not allowed. |
| Denied with a bare `false`, or `{ allowed: false }` with no `reason` | `403` | Fail-closed "Forbidden" — whatever the request looked like. |
| `authorize` **threw**                                      | `403`  | Fail-closed — a buggy hook never accidentally opens the door. |
| Answered `{ redirectTo }`                                   | `302` / `401` | A page navigation is redirected there; an API call gets `401 { "error": "unauthenticated", "redirectTo" }`. |
| Denied, but the hook already set a `location` header       | —      | The hook's redirect stands; the guard writes no status and no body. |

### Bare `boolean` vs the enriched `{ allowed, reason }` return

`authorize` may return a plain `boolean` **or** an object,
`{ allowed: boolean, reason?: 'unauthenticated' | 'forbidden' }` (or `{ redirectTo }`, above).

The `reason` only matters on a denial (`allowed: false`):

- `reason: 'unauthenticated'` → `401`, regardless of what the request looked like.
- `reason: 'forbidden'` → `403`.
- `reason` omitted, or a bare `false` → `403`. The guard does not try to guess from the
  request whether anybody is signed in — a hook that wants the "please sign in" answer says
  so with `reason: 'unauthenticated'`.

<Callout type="warn">
The guard runs on every route that serves recorded data — every `/api/*` endpoint (including
the SSE stream, the metrics rollups and the extension surface) and the
`@adonis-agora/telescope-ui` SPA routes. You cannot accidentally leave the JSON API open while
gating the page.
</Callout>

### Redirecting instead of answering JSON

To send a visitor to your own login page instead of the access-denied page, return
`{ redirectTo }`. A page navigation gets a `302` there; the console's own API calls keep
getting JSON (`401`), so the SPA never receives your login page's HTML:

```ts title="config/telescope_ui.ts"
export default defineConfig({
  authorize: (ctx) => {
    if (!ctx.auth.user) return { redirectTo: '/login?next=/telescope' }
    return ctx.auth.user.isAdmin === true
  },
})
```

A redirect you write yourself also wins: if `authorize` calls `ctx.response.redirect(...)` and
returns `false`, the guard leaves that redirect alone instead of writing its own `403`.

### The access-denied page

The `{ "error": ... }` JSON above is what the **API** answers with — the console's own `fetch`
calls expect it. A refused **page** navigation (the `@adonis-agora/telescope-ui` shell or its
assets) gets a real page instead: a dark card in the console's visual language showing the
status, a sentence explaining the refusal, a "Back to app" link and, when you set
`accessDenied.loginHref`, a "Sign in" button pointing at your app's login page. The statuses are the same as the table above. It carries no inline script, so a nonce'd `script-src`
CSP cannot break it (its one inline `<style>` picks up `@adonisjs/shield`'s request nonce).

Tweak it with `accessDenied` — every field optional:

```ts title="config/telescope_ui.ts"
export default defineConfig({
  accessDenied: {
    brand: 'Entre Textos',           // eyebrow + <title>; default "Telescope"
    title: 'Sem acesso',             // default depends on the refusal
    message: 'Peça ao admin para liberar o console de observabilidade.',
    homeHref: '/admin',              // "Back to app"; default "/", `false` hides it
    homeLabel: 'Voltar',
    loginHref: '/entrar',            // your app's login page; default: no "Sign in" button
    loginLabel: 'Entrar',
    accent: '#f59e0b',               // any CSS colour; default: the console's magenta
  },
})
```

Or replace it. Pass a function and it receives the refusal (`status`, `reason` —
`'unauthenticated'` or `'forbidden'` — `basePath`, `loginHref`, and the CSP `nonce` when there is
one) plus the same context the `authorize` hook gets. Return an HTML string to have it served with
the right status; answer the request yourself and return nothing to make the guard stand down:

```ts title="config/telescope_ui.ts"
export default defineConfig({
  accessDenied: (info, ctx) => {
    if (info.reason === 'unauthenticated') {
      ctx.response.status(302).header('location', `/login?next=${info.basePath}`)
      return
    }
    return `<!doctype html><title>${info.status}</title><h1>Sem acesso</h1>`
  },
})
```

An `authorize` hook that already wrote a redirect still wins, with or without `accessDenied`.

## Security notes

- **Set `authorize` before you deploy.** Without it the production console answers `403` to
  everyone, you included.
- **Source secrets from the environment.** Read the `authorizeByToken` token with
  `env.get(...)`; never hardcode it in `config/telescope_ui.ts`.
- **Obscure paths are defense in depth, not auth.** Changing `path` to `/__telescope`
  raises the bar for a drive-by scan; it does not replace the guard.
