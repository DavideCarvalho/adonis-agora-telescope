A turnkey web dashboard for browsing recorded entries. It mounts a single inline-HTML page
and a small JSON API directly onto your AdonisJS router — no separate service, no build
step — all served from the headless [`TelescopeService`](/docs/telescope/packages/core#headless-api),
behind a configurable [auth guard](/docs/telescope/dashboard/auth).

`configure` registers `@agora/telescope-ui/telescope_ui_provider` and publishes
`config/telescope_ui.ts`. Open `http://localhost:3333/telescope`.

## How it mounts

On boot the provider:

1. reads `config/telescope_ui.ts`;
2. resolves the live store from the core's runtime slot (same handle the watchers record
   through — no DI);
3. registers routes under the configured prefix via the AdonisJS router — the HTML page at
   the root, the JSON API under `<path>/api/*`, each behind the `authorize` guard.

<Callout type="warn">
If `@agora/telescope` isn't enabled/booted, the store slot is `null` and the provider
registers **no routes** (warn-logged) rather than crashing — the dashboard simply doesn't
exist until the core is running.
</Callout>

## What it serves

| Route                              | Serves                                                       |
| ---------------------------------- | ----------------------------------------------------------- |
| `GET <path>`                       | The inline-HTML dashboard page.                             |
| `GET <path>/api/entries`           | List (filterable, capped). Compact `EntrySummary` rows.     |
| `GET <path>/api/entries/:id`       | One entry with full `content`, or 404.                      |
| `GET <path>/api/trace/:traceId`    | Every entry on a trace.                                     |
| `GET <path>/api/stats`             | `{ count, topFamilies, topTags }`.                          |
| `GET <path>/api/meta` *(if any extension)*           | Contributed dashboards + entry types.     |
| `GET <path>/api/ext/:ext/data/:provider` *(if any extension)* | One data provider's result.      |

The dashboard HTML is read once per process and cached; the API base path is injected into
it at render time. See the [dashboard tour](/docs/telescope/dashboard) for the full API
shape and query parameters.

## Configuration

```ts title="config/telescope_ui.ts"
import { defineConfig } from '@agora/telescope-ui'

export default defineConfig({
  enabled: true,
  path: '/telescope',
  // authorize: (ctx) => ctx.auth?.user?.isAdmin === true,
  // credentials: { token: env.get('TELESCOPE_UI_TOKEN') },
})
```

| Key           | Default        | Description                                                       |
| ------------- | -------------- | --------------------------------------------------------------- |
| `enabled`     | `true`         | Master switch; `false` registers no routes.                    |
| `path`        | `/telescope`   | URL prefix (normalized to leading slash, no trailing slash).   |
| `authorize`   | default policy | Access-decision hook — [Dashboard auth](/docs/telescope/dashboard/auth). |
| `credentials` | `{}`           | Built-in token / HTTP Basic gate for the default policy.        |

## Build your own UI

The data lives behind the documented JSON API, so the shipped dashboard is optional.
Disable it and point your own front end (an admin page, a Grafana panel, a CLI) at the same
`<path>/api/*` endpoints, or read `TelescopeService` directly. The package also exports its
framework-light building blocks — `TelescopeApi`, `renderDashboard`, the `enforceGuard`
guard, and `toSummary` / `buildQuery` helpers — if you want to assemble a custom mount.

## Peer dependencies

Only `@adonisjs/core` (`^6.12.0`). The dashboard is plain inline HTML — there is no React,
Vue, or build toolchain to install.
