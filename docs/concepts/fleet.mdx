Every instance of an app sends a heartbeat every 15 seconds: the web server and each worker
(`node ace durable:work`, `node ace queue:work`). The control plane (or a standalone
app, for its own replicas) keeps the last one of each instance and shows the fleet: per app, how
many instances are up, starting, draining or gone, which versions they run, the deploys, the hosts
in a restart loop and the [health checks](/docs/telescope/concepts/health-checks) that are failing.

It is on by default. Nothing to add for the defaults.

## What an instance sends

| Field | From |
| --- | --- |
| app | The token on a control plane (never the heartbeat). `fleet.app` on a standalone app. |
| role | `web` for the HTTP server, the command's name for a worker (`durable:work`). `fleet.role` overrides it. |
| host | `fleet.host`, else `HOSTNAME`, else the OS hostname (a pod's name in Kubernetes). |
| version | `fleet.version`, else `GIT_SHA`, `COMMIT_SHA`, `SOURCE_VERSION`, `RENDER_GIT_COMMIT`, `RAILWAY_GIT_COMMIT_SHA`, `VERCEL_GIT_COMMIT_SHA`, `HEROKU_SLUG_COMMIT` or `K_REVISION`, else the app's `package.json` version. |
| state | `starting` while the app boots, `ready` once it serves (a worker: once its command starts), `draining` from the shutdown signal (`SIGTERM`, `SIGINT`) on. |
| boot time | When the process started. |
| checks | The state of each [health check](/docs/telescope/concepts/health-checks). |
| buffer | On a tenant: entries waiting, dropped and sent, and how far behind the buffer is. |

A tenant sends its heartbeat with its entries, over the same
[transport](/docs/telescope/concepts/transports) (HTTP, queue, BullMQ, Redis or durable). It never
takes a place in the entry buffer, so a full buffer cannot hide the instance.

## Workers

An ace command that keeps running (`static options = { staysAlive: true }`, as `durable:work` and
`queue:work` set) is a worker: it shows up in the fleet under its command's name, next to the web
instances. One-off commands (migrations, `telescope:*`, `make:*`) and tests send nothing.

A worker runs the [health checks](/docs/telescope/concepts/health-checks) and sends their state
with its heartbeat. It mounts no `health` route and sends no `fleet.url`, so service discovery
never routes to it.

```ts title="config/telescope.ts"
export default defineConfig({
  fleet: {
    // The default: the web server and long-running ace commands.
    report: ['web', 'worker'],
  },
})
```

| `report` entry | Sends a heartbeat |
| --- | --- |
| `'web'` | The HTTP server. |
| `'worker'` | An ace command with `staysAlive`. |
| `'scheduler:run'` | That ace command, `staysAlive` or not. |
| `'console'` | Every ace command. |

`report: ['web']` keeps workers out of the fleet.

## States

| State | Meaning |
| --- | --- |
| up | It said `ready` in its last heartbeat. |
| starting | It is booting. |
| draining | It received the shutdown signal. |
| gone | No heartbeat for more than 3 of its intervals. |

The control plane's clock decides: an instance's clock cannot keep it alive.

**Deploys.** A new version showing up among an app's instances is a deploy. The console shows each
one with its rollout progress (live instances on the new version, of all live instances) until no
live instance runs another version.

**Restart loops.** A host that booted 3 times within 10 minutes is in a restart loop (a pod in
`CrashLoopBackOff` keeps its name).

## Configuration

```ts title="config/telescope.ts"
import env from '#start/env'
import { defineConfig } from '@adonis-agora/telescope'

export default defineConfig({
  fleet: {
    interval: '15s',
    version: env.get('GIT_SHA'),
    restartLoop: { restarts: 3, within: '10m' },
    retention: '7d',
  },
})
```

| Key | Default | Effect |
| --- | --- | --- |
| `interval` | `'15s'` | How often an instance sends a heartbeat. |
| `app` | `APP_NAME`, else the package.json `name` | The app's name on a standalone app or a control plane. A tenant is named by its token. |
| `version` | see above | A string, or a function returning one. |
| `host` | `HOSTNAME`, else the OS hostname | |
| `goneAfter` | `3` | Missed heartbeats before an instance is gone. |
| `retention` | `'7d'` | How long a gone instance is kept, with its deploy and restart history. |
| `restartLoop` | `{ restarts: 3, within: '10m' }` | |
| `report` | `['web', 'worker']` | Which processes send a heartbeat (see [Workers](#workers)). |
| `role` | `web`, or the command's name | This process's role in the fleet. |
| `store` | `'auto'` | Where instances are kept: a `telescope_instances` table next to a Lucid entries store (same connection and `schema`), else memory. `'memory'`, or a store of your own. |

`fleet: false` turns heartbeats and the fleet off.

<Callout type="info">
With `storage.lucid({ autoCreateTable: true })` the table is created on first use. Otherwise run
the migration `node ace configure @adonis-agora/telescope` publishes
(`create_telescope_instances_table`), with the same `schema` as `storage.lucid()`.
</Callout>

On a standalone app with several replicas, keep entries in Lucid so the replicas share the table
and each one sees the others. With the memory store each replica only sees itself.

## The Fleet page

**Fleet** in the console's Monitor section (also in ⌘K) shows, for the app picked in the App
picker or for every app:

- the instance counts by state;
- each instance: host, role, version, uptime, last heartbeat, health and send buffer (hover the
  last heartbeat for when the instance was first and last seen);
- a role filter (all roles, `web`, `durable:work`, ...) when the fleet runs more than one;
- the deploy timeline with rollout progress;
- hosts in a restart loop;
- each failing check, since when, on how many instances, and the exception families recorded since
  it went bad.

A viewer limited to some apps (`apps` in `authorize`) only sees those apps' instances. Instances are
shared by every organization, so a viewer limited to some organizations sees none.

## From the CLI and MCP

```sh
node ace telescope:fleet:list
node ace telescope:fleet:list --app shop --json
```

The `telescope_get_fleet` tool on [`/mcp/agora`](/docs/telescope/packages/mcp) answers the same,
for the apps the caller may see.

Each instance in the answer (and in `GET <path>/api/fleet`) carries `createdAt` (its first
heartbeat) and `updatedAt` (its last heartbeat) as ISO 8601 strings, `null` when unknown, next to
`firstSeenAt` and `lastSeenAt` in epoch milliseconds. An instance keeps its `createdAt` when the
control plane restarts.

## Alerts

| Rule | Fires when |
| --- | --- |
| `{ type: 'instances-up', app?, role?, below, for? }` | Fewer than `below` instances of an app are up for `for` (default `'1m'`). `below: 1` pages when none is left. Counts `role` instances: `'web'` (default), a worker's command (`'durable:work'`) or `'*'`. |
| `{ type: 'restart-loop', app? }` | A host of the app is in a restart loop. |
| `{ type: 'check-down', check?, app?, for }` | A health check has been down for `for`. |
| `{ type: 'entries-dropped', app?, window, threshold? }` | The app's instances dropped at least `threshold` (default 1) entries within `window`. |

They fire and resolve per app on every channel. See
[Alerts](/docs/telescope/packages/alerts#fleet-rules).
