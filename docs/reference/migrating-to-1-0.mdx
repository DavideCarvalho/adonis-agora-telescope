Most apps only change two version ranges. Your providers, middleware, dashboard routes and the
rest of `config/telescope*.ts` stay as they are. The sections below cover the options that were
removed.

<Callout type="info">
While 1.0 is in release candidate, install it with the `rc` tag:
`pnpm add @adonis-agora/telescope@rc @adonis-agora/telescope-ui@rc`.
</Callout>

## Update the version ranges

A `0.x` range does not match `1.0.0`, and a `2.x` range does not match `3.0.0`, so a plain
update keeps you on the old lines. Change the ranges in `package.json`.

Before:

```json title="package.json"
{
  "dependencies": {
    "@adonis-agora/telescope": "^0.27.1",
    "@adonis-agora/telescope-ui": "^2.1.0"
  }
}
```

After:

```json title="package.json"
{
  "dependencies": {
    "@adonis-agora/telescope": "^1.0.0",
    "@adonis-agora/telescope-ui": "^3.0.0"
  }
}
```

Then install:

```sh
npm install
```

</Tab>

```sh
pnpm install
```

## Run on Node.js 24 or newer

Both packages declare `"engines": { "node": ">=24" }`.

Before:

```txt title=".nvmrc"
22
```

After:

```txt title=".nvmrc"
24
```

Use the same version in your Dockerfile, CI and hosting settings.

## Console access: `credentials` is replaced by `authorize`

`config/telescope_ui.ts` no longer takes `credentials: { token, basic }`, and the console no
longer reads `?token=` or HTTP Basic. Without `authorize`, the console is open outside production
and answers `403` to every request in production. The `TELESCOPE_UI_TOKEN` and
`TELESCOPE_UI_PASSWORD` variables are no longer read; remove them from `start/env.ts` and `.env`.

For token access, use `authorizeByToken`. It reads only the `Authorization: Bearer <token>`
header.

Before:

```ts title="config/telescope_ui.ts"
import env from '#start/env'
import { defineConfig } from '@adonis-agora/telescope/ui'

export default defineConfig({
  credentials: {
    token: env.get('TELESCOPE_UI_TOKEN'),
    basic: { username: 'admin', password: env.get('TELESCOPE_UI_PASSWORD') },
  },
})
```

After:

```ts title="config/telescope_ui.ts"
import env from '#start/env'
import { authorizeByToken, defineConfig } from '@adonis-agora/telescope/ui'

export default defineConfig({
  authorize: authorizeByToken({ token: env.get('CONSOLE_TOKEN') }),
})
```

```ts title="start/env.ts"
export default await Env.create(new URL('../', import.meta.url), {
  CONSOLE_TOKEN: Env.schema.string(),
})
```

Send the header instead of the query string:

```sh
# Before
open 'https://app.example.com/telescope?token=s3cr3t'
# After
curl -H 'Authorization: Bearer s3cr3t' https://app.example.com/telescope/api/entries
```

For people, gate the console on your app's own auth instead:

```ts title="config/telescope_ui.ts"
import { defineConfig } from '@adonis-agora/telescope/ui'

export default defineConfig({
  authorize: (ctx) => ctx.auth.user?.isAdmin === true,
})
```

If you had neither `authorize` nor `credentials`, the console is still open outside production
and still closed in production; it now answers `403` there (it was `401`) and logs a warning at
boot until you set `authorize`.

The JSON errors are now lowercase codes: `{ "error": "forbidden" }` (`403`) and
`{ "error": "unauthenticated" }` (`401`, with `redirectTo` when `authorize` returned one).

`config/telescope_mcp.ts` keeps its own `credentials` option; it is unchanged.

## `storage.memory({ limit })` is now `maxEntries`

The memory driver takes its cap as `maxEntries`, the same name `InMemoryTelescopeStore` uses.
The value and the default (1000) are unchanged.

Before:

```ts title="config/telescope.ts"
import { defineConfig, storage } from '@adonis-agora/telescope'

export default defineConfig({
  store: 'memory',
  stores: {
    memory: storage.memory({ limit: 5000 }),
  },
})
```

After:

```ts title="config/telescope.ts"
import { defineConfig, storage } from '@adonis-agora/telescope'

export default defineConfig({
  store: 'memory',
  stores: {
    memory: storage.memory({ maxEntries: 5000 }),
  },
})
```

## The dashboard reads its API base from the page only

The dashboard takes its API base from the config block the provider writes into the page, or
falls back to `<mount>/api`. It no longer reads a `window.__TELESCOPE_DASHBOARD_BASE__` global.
If you embed the client yourself, pass the base to it.

Before:

```ts title="resources/js/telescope.ts"
import { TelescopeClient } from '@adonis-agora/telescope-ui/client'

window.__TELESCOPE_DASHBOARD_BASE__ = '/admin/telescope/api'
const telescope = new TelescopeClient()
```

After:

```ts title="resources/js/telescope.ts"
import { TelescopeClient } from '@adonis-agora/telescope-ui/client'

const telescope = new TelescopeClient({ baseUrl: '/admin/telescope/api' })
```

## `coverage.legacyAgentLib` is gone from the AI summary

The AI summary (`GET <path>/api/metrics/ai`, `TelescopeClient#ai()`, and the `AiCoverage` type)
no longer has a `legacyAgentLib` flag. It marked apps running an `@adonis-agora/agent` release
older than 0.93.0. Read `usageEvents` instead: zero means no `usage.recorded` events in the
window.

Before:

```ts title="app/controllers/ai_report_controller.ts"
import type { HttpContext } from '@adonisjs/core/http'
import { TelescopeClient } from '@adonis-agora/telescope-ui/client'

export default class AiReportController {
  async show({ response }: HttpContext) {
    const ai = await new TelescopeClient({ baseUrl: 'http://localhost:3333/telescope/api' }).ai()
    if (ai.coverage.legacyAgentLib) return response.ok({ status: 'agent too old' })
    return response.ok({ spend: ai.spend.totalUsd })
  }
}
```

After:

```ts title="app/controllers/ai_report_controller.ts"
import type { HttpContext } from '@adonisjs/core/http'
import { TelescopeClient } from '@adonis-agora/telescope-ui/client'

export default class AiReportController {
  async show({ response }: HttpContext) {
    const ai = await new TelescopeClient({ baseUrl: 'http://localhost:3333/telescope/api' }).ai()
    if (ai.coverage.usageEvents === 0) return response.ok({ status: 'no usage recorded' })
    return response.ok({ spend: ai.spend.totalUsd })
  }
}
```
