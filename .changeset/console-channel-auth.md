'@adonis-agora/telescope': minor
---

Federated console commands are authenticated (security fix). Previously any client that could publish on the app's Redis could replay requests, retry or enqueue jobs, and forge answers.

**Breaking:** an app with `consoleCommands`, and a console with `apps.federated.<app>.commands`, now need a way to authenticate. When none resolves, the web process refuses to boot with a message naming the options (ace commands are never affected). The modes:

- **Together with `@adonis-agora/crypto`: nothing to configure.** When crypto is booted in the app (detected through the `agora.crypto` binding) and no mode is set, commands are sealed with the `console-telescope` key (`aes256-gcm`) of the owning app's crypto partition (`apps.federated.<app>.partition`, default the key). Embedded crypto creates the key at boot; a crypto tenant creates it when its client may, or logs the exact `crypto:keys:create` command to run. A console that is a crypto tenant seals through its crypto server (`crypto:seal:console-*`). Grants: none for the apps (an app opens its own `console-*` keys); a separate crypto app's console needs `crypto:seal:console-*`. `crypto: false` turns it off.
- **Together with authkit (calls between apps): nothing to configure.** With `authkit.client` configured for calls between apps and no `token` / `verifyTenant`, the console attaches an app-call token to each sealed command and the app verifies it with authkit's app-caller verifier. The token's audience binds it to the app, and its capabilities cap the command. Combines with crypto: there the token is optional (a crypto command without one is accepted; one that is sent must pass and caps the command), as with a control plane's own `verifyTenant`. Only explicit `crypto` + explicit `verifyTenant` makes it mandatory. `token: false` / `verifyTenant: false` turn it off.
- **Explicit crypto**: `crypto: { cipher, key?, owns? }` on both sides, with any cipher that has `encrypt`/`decrypt` (crypto's, or your own KMS; `owns` recognises its ciphertext format). The default key was renamed from `telescope-console` to `console-telescope`.
- **Token mode**: `commands.token` + `commands.publicKey` (printed by `node ace telescope:console:key`) on the console, `consoleCommands.verifyTenant` on the app; a classic token's partition must be `consoleCommands.partition` (default the tenant partition, else the app name, else the prefix). On a control plane, `verifyTenant` defaults to the control plane's own, which is safe because ingest tokens carry no console capability. Only an explicit `verifyTenant` (or `false`) turns the fallbacks off. This mode stays available next to crypto whenever a verifier and an `APP_KEY` exist.
- **Shared secret**: the same `secret` (16+ characters) on both sides.

The console always sends the viewer's capabilities (the `capabilities` its `authorize` returns, a new optional field, kept to the telescope console set; all of `telescope:console:read`, `:queues` and `:replay` when it returns none), and the app refuses a command without them (`403`, `capabilities-required`). Every verb needs its capability, reads included. In token mode the token's capabilities cap them too. Commands older than a minute are refused, replays run once, and forged answers are ignored. `consoleCommands.actions` (replay and queues, both off by default) still gates actions. Refused commands are logged at `warn`, and each side logs the mode it resolved at boot. `telescope:console:write` is an alias of the actions (`queues` and `replay`), and `telescope:console:*` grants everything. The viewer's capabilities (or `access: 'read'`) also restrict this console's own replay and queue actions (`403`, "The viewer lacks …"), and the dashboard disables what the viewer can't do. When `authorize` returns no capabilities, the console keeps full access. The console's `authorize` contract (`console_authorize.ts`) is now the shared Agora one: it adds `capabilities`, `access` and `anyAuthorize`. A malformed `apps` or `tenants` list now allows none instead of being ignored. A lazy-imported authorizer class is remembered per resolved guard. `apps.federated.<app>.commands` is now on by default, like every Agora console's `actions`. Omitted, it is `{}` (prefix `telescope`, the default Redis connection), so an entry that cannot authenticate refuses to boot unless it sets `commands: false`. When several entries omit it, they stay browse-only and the boot log says how to enable each. Local profile arming, extension actions and AI diagnosis need `telescope:console:write`. Every console-capability check goes through the matcher shared by every Agora lib (`console_capabilities.ts`): `telescope:console:write` implies read, `*`, `telescope:*` and `telescope:console:*` allow everything, and a `*` anywhere but a whole last segment grants nothing. authkit counts only when its calls between apps are actually configured (a usable verifier or token source), so a binding without them is a boot error rather than a runtime surprise. The console key is created once with a retry on the first command; a crypto tenant probes it with a dummy decrypt (never `getKey`) and logs one actionable line. A command is checked in this order: verb, capabilities, token, viewer, partition and actions. Boot errors are a `ConsoleAuthConfigError` with the uniform Agora messages, and both the boot logs and the doctor use the uniform mode labels. The app's line ends with `; actions on|off (…)`. The console key appears only as a short id. A timed-out command says the app may have refused it. Garbage on the channel is logged once per reason and never crashes the app. In token mode the app publishes its console public key in authkit's key directory (`publishAppKey`, purpose `console:telescope`), and a console without `commands.publicKey` looks it up there (`appKey`). An explicit `publicKey`, in `x25519:` or JWK form, still wins. Apps need no crypto grant to open their own `console-*` keys, and a key missing on a crypto tenant is now an info line: the crypto server provisions it on the console's first seal. A refused command is logged as `console commands: refused a command (<reason>)`, with uniform reasons. A tenant's discovery long poll now runs only in processes that serve (web, or a `staysAlive` ace command), so `node ace` commands of a tenant app exit, and termination aborts it. A Hub with both crypto and authkit picks the mode per app at the first command: token mode when the app publishes a key in authkit's directory, else crypto. The choice is cached and re-made after 5 minutes or after a failed command. An app with crypto active does not publish its token key. An auto-chosen token that cannot be minted falls back to crypto. In crypto mode, an app-call token that cannot be minted is skipped with one warning instead of failing the command. `APP_KEY` is read from `app.appKey`, then `config/encryption.ts`, then the environment. The boot error mentions authkit. The key check uses crypto's `hasKey` when available, so it adds no audit noise. New `agora:doctor` checks: `telescope.console-commands` reports the mode on each side, and the deep `telescope.console-commands-key` probes the crypto key.

Redaction now matches sensitive key names in any spelling instead of only exact names. `accessToken`, `refreshToken`, `password_confirmation`, `newPassword`, `x-auth-token`, `_csrf`, `sessionId`, `signingKey`, `otp`, `cpf` and similar keys are masked. Identifiers and counts such as `cacheKey`, `publicKey`, `inputTokens` and `authorName` are kept. A new `redact.allow` option keeps a false positive unmasked.
